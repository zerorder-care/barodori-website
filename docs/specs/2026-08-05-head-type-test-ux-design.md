# 아기 두상 유형 테스트 — 와이어프레임 기반 UX 설계

- 날짜: 2026-08-05
- 대상: 바이럴 페이지(아기 두상 유형 테스트) 전체 화면 흐름·구성·상태
- 상태: 합의 완료
- 선행 문서: `docs/specs/2026-08-05-head-type-test-copy-design.md` (모든 노출 문구는 카피 스펙을 따른다)
- 와이어프레임: `design/barodori-website.pen` 내 "두상 테스트" 섹션

## 1. 설계 원칙

- **몰입형 스텝 플로우**: MaBTI류 바이럴 테스트 관례. 전용 화면에서 인트로 → 입력 → 결과를 한 호흡에 진행한다. "30초면 끝" 약속을 UX가 지킨다.
- **모바일 퍼스트**: 유통 채널(맘카페·인스타그램)이 모바일 중심. 데스크톱은 중앙 고정 모바일 폭(≈480px) 컬럼 + 브랜드 톤 배경으로 동일 레이아웃을 쓴다.
- **사진 노출 최소화**: 분석 중·결과 화면 어디에도 촬영한 사진과 마스크 윤곽선을 표시하지 않는다(확정). "사진은 기기 안에서만 처리돼요" 메시지와 시각적으로 일관되게, 사진은 촬영·정렬 단계에서만 보인다.
- **막다른 화면 금지**: 모든 실패 상태(품질 실패, 권한 거부, 모델 로드 실패)는 문항 플로우로 이어지는 출구를 가진다.
- 의학용어·수치 미노출, 유형 동등 취급, 놀이 확장 프레임 등 카피 원칙은 카피 스펙 §1을 따른다.

## 2. 정보 구조·라우팅

- 진입점: 사이트 상단 탭 "두상 테스트" → `/{locale}/head-test`.
- 테스트 내부(인트로·사진·문항)는 `/head-test` 단일 라우트의 클라이언트 스텝 전환. 새로고침 시 인트로로 복귀해도 무방하다(30초 플로우, 저장할 진행 상태가 얇음).
- 결과만 별도 라우트 `/head-test/result/[type]` (type: `ttaomi`·`banguri`·`ppyojogi`·`jjanggu`·`donggeuri` — 카드·캐릭터 에셋 파일명과 동일한 슬러그). 유형별 OG 메타에 `docs/specs/assets/head-type-cards/{type}-og.png`를 물려 공유 링크가 유형 카드를 미리보기로 노출한다.
- 결과 URL에는 유형만 담는다. 월령·방향 등 개인화 데이터는 URL에 싣지 않고 기기 안(클라이언트 상태)에서만 쓴다 — 공유받은 사람은 개인화 없는 기본 결과 화면을 본다.
- 딥링크 파라미터·계측 이벤트 정의는 "공유·앱 진입 플로우" 티켓 소관. 이 설계는 공유 버튼의 위치와 동작 슬롯만 정의한다.

### 테스트 내 헤더

사이트 공통 헤더 대신 최소 헤더를 쓴다: 좌측 소형 로고(홈 링크), 우측 없음. 문항 플로우에서는 뒤로 가기 + 진행바가 헤더를 대체한다.

## 3. 화면 흐름

```
인트로(선택 겸)
 ├─ [사진으로 30초 만에] → 촬영 화면 ─┬─ 셔터 → 월령 질문(분석 병행) → 분석 중 ─┬─ 성공 → 결과
 │                                  │                                      └─ 품질 실패 → 폴백 안내 → 문항 or 재촬영
 │                                  └─ 갤러리 → 회전 정렬 → (위와 동일)
 └─ [사진 없이 문항으로] → 문항 1…7 → 판정 → 결과
```

## 4. 화면별 설계

### 4.1 인트로 (선택 겸)

위→아래 순서:

1. 소형 로고
2. 캐릭터 5종 일러스트 무리 (`head-type-characters/`)
3. 훅 타이틀: "우리 아기는 어떤 유형일까?" + 서브 "사진 한 장이면 30초 만에 끝나요"
4. Primary 버튼: **사진으로 30초 만에** / Secondary 버튼: **사진 없이 문항으로**
5. 🔒 개인정보 안내: "사진은 기기 안에서만 처리되고 어디에도 전송되지 않아요"
6. 면피 한 줄(소형): "재미로 보는 유형 테스트예요" (전체 문구는 결과 화면에, 카피 스펙 §8)

### 4.2 촬영 화면 (사진 플로우)

- 전면: 카메라 프리뷰(위에서 내려다본 구도 안내 문구: "아기 머리가 위에서 보이게 맞춰 주세요").
- **조준선 오버레이** (기본 ON, 우상단 토글로 OFF 가능):
  - 머리 실루엣 타원 — 중앙 위치·크기 유도
  - "코가 위로" 방향 표시 — 좌/우 판정 규약의 전제
  - 십자선 — 기울기 기준
- 하단: 셔터 버튼(중앙), 갤러리 버튼(좌), 조준선 토글 상태 표시.
- 상단 상시 배지: "🔒 기기 안에서만 처리돼요".
- 카메라 권한 거부 시: 프리뷰 자리에 안내 + [갤러리에서 고르기] / [문항으로 하기].

### 4.3 회전 정렬 (갤러리 업로드 시)

- 업로드한 사진 미리보기 + "코가 위를 향하게 돌려 주세요" 안내.
- 90° 회전 버튼(반복 탭으로 4방향 순환). 참고용 타원·"코가 위로" 마커를 미리보기 위에 겹쳐 보여준다.
- [이 방향으로 분석하기] 버튼으로 진행.

### 4.4 월령 질문 + 분석 중

- 분석 시작 직후, 대기 화면에서 월령 1문항을 받는다: "아기가 태어난 지 얼마나 됐나요?" — [아직 3개월이 안 됐어요] / [3개월이 지났어요]. 놀이 팁 분기(카피 스펙 §5)에만 쓰며 판정에는 미사용.
- 분석이 먼저 끝나도 월령 응답까지 대기 후 결과로 전환한다(체감 로딩을 질문이 흡수).
- 분석 중 표시는 캐릭터 애니메이션 + 진행 문구("동글동글 재는 중…" 등 로테이션)만. 사진·윤곽선은 표시하지 않는다.
- 월령 응답 후에도 분석이 진행 중이면 동일 애니메이션 유지.

### 4.5 사진 예외 상태

| 상태 | 처리 |
|---|---|
| 마스크 sanity check 실패 | "사진으로는 판정이 어려웠어요. 조명이 밝고 머리가 화면에 꽉 차게 다시 찍으면 좋아요." + [문항으로 이어하기](권장, primary) / [다시 찍기](secondary) |
| 조준선 OFF + sanity check 간신히 통과 | 결과 진행은 허용하되 분석 전 안내: "가이드에 맞춰 다시 찍으면 더 정확해요" + [그대로 진행] / [다시 찍기] |
| 모델 로드 실패 (저사양·구형 브라우저·네트워크) | "이 기기에서는 사진 분석이 어려워요" + [문항으로 하기] 단일 출구 |
| 카메라 권한 거부 | 4.2 참조 — 갤러리·문항 출구 |

"간신히 통과" 판정 기준(마스크 면적·모양 검사의 경계 범위)은 유형 경계값 조정 티켓에서 수치로 확정한다.

### 4.6 문항 플로우

- 한 화면에 한 문항. 선택지 탭 즉시 다음 문항 자동 진행(선택 확인 버튼 없음).
- 헤더: 뒤로 가기(이전 문항) + 진행바(7칸).
- 문항 순서는 쉬운 관찰 → 습관 → 월령 순. 배점·경계값은 "유형 경계값 조정" 티켓 소관이고, 아래 문구는 UX 초안이다.

| # | 문항 | 선택지 | 비고 |
|---|---|---|---|
| 1 | 아기를 위에서 내려다보면 머리 모양이 어떤 느낌인가요? | 동그란 편 / 앞뒤로 길쭉한 편 / 좌우로 넓적한 편 / 한쪽이 살짝 기울어진 느낌 / 잘 모르겠어요 | 핵심 모양 축. "잘 모르겠어요" 선택 시 습관 문항(5·6) 2배 가중치 |
| 2 | 옆에서 봤을 때 뒤통수 라인은 어떤가요? | 봉긋하게 나온 편 / 완만하게 둥근 편 / 납작한 편 / 잘 모르겠어요 | 짱구·동글이·방울이 신호 |
| 3 | 정면에서 마주 봤을 때 양쪽 귀 위치는 어때 보이나요? | 비슷해 보여요 / 한쪽이 조금 앞으로 나와 보여요 / 잘 모르겠어요 | 따옴이 관찰 신호 |
| 4 | 잘 때 고개가 주로 어느 쪽을 향해 있나요? | 왼쪽 / 오른쪽 / 양쪽 골고루 / 잘 모르겠어요 | 보조 문구 "아기 입장 기준으로 골라 주세요" 고정 노출(앱 규약과 동일). 좌/우 응답은 따옴이 방향 정보로 기기 내 저장 |
| 5 | 하루 중 등을 대고 누워 있는 시간은 어느 정도인가요? | 대부분 누워 있어요 / 안겨 있거나 엎드리는 시간도 꽤 있어요 / 잘 모르겠어요 | 방울이 원인 신호 |
| 6 | 엎드려 노는 시간을 아기가 어떻게 받아들이나요? | 좋아하고 잘 버텨요 / 조금 하다 힘들어해요 / 아직 안 해봤어요 | 짱구 신호 + 놀이 팁 개인화 |
| 7 | 아기가 태어난 지 얼마나 됐나요? | 아직 3개월이 안 됐어요 / 3개월이 지났어요 | 판정 미사용, 놀이 팁 월령 분기 전용 |

- 문항 6에 "터미타임"이라는 단어를 쓰지 않는다 — 앱 운동명과의 이름 충돌 금지 원칙(카피 스펙 §1).
- 마지막 문항 응답 후 짧은 판정 전환 화면(캐릭터 애니메이션, 1초 내외)을 거쳐 결과로 이동한다.

### 4.7 결과 화면 (`/head-test/result/[type]`)

노출 순서 (카피 스펙 §10에서 이 티켓으로 위임된 확정 사항):

1. **유형 카드**: 캐릭터 일러스트 + "우리 아기는 ○○이" + 한 줄 카피. 공유 카드와 같은 시각 단위로 화면 최상단을 차지한다.
2. **통계 한 줄**: "지금까지 테스트한 아기 중 {n}%가 {유형명}였어요." / 표본 부족 시 폴백 문구 (카피 스펙 §7).
3. **특성 본문**: 유형별 3줄 (카피 스펙 §4).
4. **놀이 팁 2개**: 월령(3개월 전/후)·따옴이 방향 분기 적용 (카피 스펙 §5). 카드 2장 + 하단 공통 안전 문구. 팁 섹션 상단에 월령 토글(3개월 전/후)을 두어 테스트를 마친 경우 응답값이 선택된 상태로, 공유 링크로 진입한 경우 "3개월 이후"가 기본 선택된 상태로 보여주되 방문자가 바꿔볼 수 있게 한다. 방향 정보가 없으면 따옴이 팁은 방향 폴백("양쪽에서 번갈아", 카피 스펙 §5)을 쓴다.
5. **공유 버튼**: primary. 유형별 공유 훅 문구(카피 스펙 §6)는 공유 시트/클립보드 텍스트로 나간다. 동작 상세는 공유 티켓 소관.
6. **앱 CTA**: "오늘 놀이가 재밌었다면, 내일은 뭐 하고 놀까요?" 헤드 + 서브 + [앱에서 놀이 이어가기] 버튼 (카피 스펙 §9). 걱정 해결 프레임 금지.
7. **병원 안내 + 면피**: 카피 스펙 §8 문구. 본문보다 작은 타이포지만 접지 않고 항상 노출한다(법률 검토 대비 — 접기 UI는 고지 미달 소지).
8. **다시 해보기** 링크(인트로로) + **다른 유형 구경하기**(5종 캐릭터 소형 리스트, 각 유형 결과 화면으로 이동).

공유(5)가 앱 CTA(6)보다 위인 이유: 페이지의 1차 목표가 바이럴 루프이고, 기획도 "공유 카드 하단에 설치 유도" 순서를 전제한다.

## 5. 접근성·모션

- 문항 선택지·버튼은 최소 44px 터치 타깃, 선택 상태는 색+형태(체크)로 이중 표시.
- 캐릭터 애니메이션은 `prefers-reduced-motion` 존중(정지 일러스트로 대체).
- 촬영 화면 조준선은 장식이 아니라 지시이므로 오버레이 토글 상태를 스크린리더에 노출한다.
- 통계·면피 등 저시력 대비 텍스트는 대비비 4.5:1 이상.

## 7. 소관 경계 (이 문서가 정하지 않는 것)

- 문항 배점·유형 경계값·sanity check 수치 → "유형 경계값 조정" 티켓.
- 공유 딥링크 구조·계측 이벤트·통계 노출 임계값 → "공유·앱 진입 플로우" 티켓.

- 비주얼 디자인(컬러·타이포·일러스트 최종형) → 와이어프레임 이후 디자인 단계.
