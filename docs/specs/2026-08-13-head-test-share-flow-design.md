# 아기 두상 유형 테스트 — 공유·앱 진입 플로우 설계 (공유 동작·계측 이벤트·통계 노출)

- 날짜: 2026-08-13
- 대상: 결과 공유의 동작과 링크 구조, 퍼널 계측 이벤트 스키마, 통계 실측 노출 전환 기준, 앱 진입 경로, 상단 탭 노출 조건
- 상태: 초안 — 구현 착수 기준이 되는 확정값이며, 이벤트 스키마의 익명성 원칙은 법률 검토 결과에 따라 보수적으로만 조정한다
- 선행 문서: `docs/specs/2026-08-05-head-type-test-copy-design.md`(공유 훅 문구), `docs/specs/2026-08-05-head-type-test-ux-design.md`(공유 버튼 위치), `docs/specs/2026-08-07-head-type-test-scoring-design.md`(익명 집계 원칙)

## 1. 원칙

- 공유 링크에는 유형 슬러그 외의 어떤 개인화 정보도 싣지 않는다. 공유받은 사람은 개인화 없는 기본 결과 화면을 본다.
- 계측 이벤트는 익명 카운트만 목적으로 한다. 어떤 이벤트에도 식별자를 만들지 않고, 개인화 값(선호 방향·월령·문항 응답 원본)은 싣지 않는다.
- 이벤트 이름과 프로퍼티는 사이트 공통 계측 컨벤션(snake_case, `locale` 포함, `lib/analytics`의 `track()`)을 따른다.

## 2. 공유 동작

결과 화면의 공유 버튼은 다음 순서로 동작한다.

1. Web Share API를 지원하는 환경에서는 시스템 공유 시트를 연다. 공유 텍스트는 유형별 공유 훅(카피 스펙 §6) 뒤에 공통 꼬리 문구를 붙인 것이고, URL은 아래 §3의 공유 URL이다.
2. 지원하지 않는 환경에서는 같은 텍스트와 URL을 클립보드에 복사하고 "링크를 복사했어요"를 잠깐 보여준다.

공유 카드 이미지는 첨부하지 않는다. 링크 미리보기는 유형별 OG 이미지가 담당하며, 이미지 파일을 직접 실어 나르면 플랫폼별 동작 편차만 커진다.

## 3. 공유 URL과 진입 구분

공유로 나가는 URL은 결과 경로에 UTM 파라미터를 붙인 형태로 고정한다.

```
/{locale}/head-test/result/{type}?utm_source=head_test&utm_medium=share
```

상단 탭 등 사이트 내부 진입은 파라미터 없이 이동하고, 바이럴 실행 티켓이 집행하는 채널별 링크는 `utm_medium`만 채널명(예: `instagram`)으로 바꿔 쓴다. 결과 화면은 `utm_medium` 값의 존재 여부로 자기 결과(테스트 직후)와 공유 유입을 구분해 계측한다. UTM은 계측 표준이라 별도 파라미터 체계를 만들지 않는다.

## 4. 계측 이벤트 스키마

| 이벤트 | 시점 | 프로퍼티 |
|---|---|---|
| `head_test_view` | 인트로 노출 | `locale`, `source`(utm_medium 값 또는 `direct`) |
| `head_test_start` | 인트로에서 경로 선택 | `locale`, `path`(`photo`·`questions`) |
| `head_test_photo_fallback` | 사진 경로 이탈 분기 | `locale`, `reason`(`permission`·`quality`·`model`·`barely_retake`) |
| `head_test_complete` | 판정 확정(결과 이동 직전) | `locale`, `type`, `path`, `quality`(사진 경로만: `pass`·`edge`) |
| `head_test_result_view` | 결과 화면 노출 | `locale`, `type`, `entry`(`own`·`share`·`direct`) |
| `head_test_share_click` | 공유 버튼 클릭 | `locale`, `type`, `method`(`sheet`·`clipboard`) |
| `head_test_app_cta_click` | 앱 CTA 클릭 | `locale`, `type` |
| `head_test_retry_click` | 다시 해보기 클릭 | `locale`, `from` |
| `head_test_other_type_click` | 다른 유형 구경 클릭 | `locale`, `from`, `to` |

`entry`는 자기 기기에서 테스트를 마치고 넘어온 경우가 `own`, `utm_medium=share`로 들어온 경우가 `share`, 그 외가 `direct`다. 티켓 이름이 요구하는 **유형별 공유율은 `head_test_share_click`을 같은 유형의 `head_test_result_view`(entry=own)로 나눈 값**으로 정의한다.

### 익명성 규칙 (계측의 금지선)

- 선호 방향(`preferredSide`), 월령 구분, 문항 응답 원본은 어떤 이벤트에도 싣지 않는다. 이 값들은 기기 안에서 놀이 팁 분기에만 쓰인다는 약속이 서비스의 방어선이기 때문이다.
- 유형·경로·품질 등급은 개인의 신체 정보가 아니라 콘텐츠 소비 결과로 취급해 싣는다. 다만 프로퍼티를 추가할 때는 조합으로 개인을 좁힐 수 있는지(준식별)를 먼저 따진다.
- 문항 단위 진행 이벤트는 만들지 않는다. 이탈 분석은 `start` 대비 `complete` 비율로 충분하고, 응답 내용 계측은 금지선과 맞닿아 있어 얻는 것보다 잃는 것이 크다.

## 5. 통계 실측 노출 전환

- 집계 소스는 `head_test_complete` 이벤트의 유형 분포다. 별도 수집 서버를 만들지 않는다.
- 결과 화면의 통계 문구는 **전체 완료 수가 1,000 이상이고 다섯 유형 모두 20건 이상**이 된 시점부터 실측 %로 전환한다. 하한 1,000은 %가 일 단위로 출렁이지 않을 최소 표본이고, 유형별 20은 희소 유형이 0%로 표기되는 상황을 막는다.
- 실측 %는 반올림한 정수로 표기하고, 전환 전에는 표본 부족 폴백 문구를 유지한다.
- 반영 방식은 코드의 정적 상수 모듈로 시작한다. 운영자가 집계 대시보드에서 분포를 읽어 주 1회 갱신하고, 갱신 자동화는 트래픽이 이를 정당화할 때 별도 티켓으로 만든다.

## 6. 앱 진입 플로우

- 앱 CTA는 `/{locale}/install?utm_source=head_test&utm_medium=result_cta`로 이동한다. 설치 페이지는 스토어 상태(라이브·QR·베타)를 이미 처리하고 있으므로 결과 화면이 스토어 링크를 직접 다루지 않는다.
- CTA 클릭은 `head_test_app_cta_click`으로, 설치 페이지 도착 후의 스토어 클릭은 기존 `cta_install_click`으로 각각 계측되어 퍼널이 이어진다.
- 스토어 설치 어트리뷰션(설치가 테스트에서 왔는지의 스토어 단 기여 측정)은 스토어 리퍼러의 한계 때문에 이 설계의 범위에서 제외한다. 퍼널 계측으로 충분히 방향을 읽을 수 있다.

## 7. 상단 탭 노출

- 사이트 헤더에 "두상 테스트" 탭을 추가하는 시점은 다음 세 조건이 모두 갖춰진 뒤다: ① 법률 검토를 반영한 면피·병원 안내 확정 문구 배포, ② 이 설계의 계측 이벤트 배포, ③ 모델 URL 환경 변수 설정 확인.
- 탭 진입은 UTM 없이 이동하고, 인트로의 `head_test_view`가 `source=direct`로 잡는다.

## 8. 소관 경계 (이 문서가 정하지 않는 것)

- 공유·계측·탭의 코드 구현 → "공유 동작·앱 CTA·퍼널 계측 구현" 티켓.
- 채널별 집행 링크와 광고 문구 → "바이럴 실행" 티켓. 광고 문구는 법률 검토의 금지 표현 목록을 따른다.
- 면피·병원 안내 최종 문구와 익명 집계 관련 법적 확인 → "법률 검토" 티켓.
