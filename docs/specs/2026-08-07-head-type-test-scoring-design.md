# 아기 두상 유형 테스트 — 판정 기준 설계 (경계값·문항 배점·품질 검사)

- 날짜: 2026-08-07
- 대상: 사진 측정 판정의 경계값, 문항 플로우의 배점과 판정 절차, 마스크 품질 검사(sanity check) 수치
- 상태: 초안 — 여기 적힌 수치는 구현 착수 기준이 되는 초기값이며, 실측 분포가 쌓이면 §6의 절차로 조정한다
- 선행 문서: `docs/specs/2026-08-03-head-type-test-design.md`(기획), `docs/specs/2026-08-05-head-type-test-copy-design.md`(카피), `docs/specs/2026-08-05-head-type-test-ux-design.md`(UX)
- 근거 데이터: ONNX 스파이크 결과(노션 티켓 "ONNX Runtime Web 모델 추론 검증") — 촬영 각도만 바꿔도 CVAI가 2.19~4.26으로 흔들려 경계 3.5를 넘나든 실측이 이 문서의 품질 검사 설계를 정당화한다

## 1. 원칙

- 이 문서의 모든 수치는 내부 판정 전용이며, 사용자에게 보이는 어떤 화면에도 노출하지 않는다.
- 판정은 결정적이어야 한다. 같은 입력(사진 또는 응답 조합)은 언제나 같은 유형을 낸다.
- 구현은 이 문서의 표를 하나의 상수 모듈로 옮겨 단일 출처로 삼는다. 수치를 조정할 때는 상수 모듈과 이 문서를 함께 바꾼다.
- 다섯 유형은 판정 구조 안에서도 동등하다. 임계값의 높낮이는 신호의 확실성을 반영할 뿐, 유형 간 서열이 아니다.

## 2. 사진 측정 판정

측정 로직은 스파이크에서 이식을 마친 TS 포트를 그대로 쓴다. 마스크에서 AP·ML·D1·D2 축 길이를 재고 CI = ML/AP×100, CVAI = |D1−D2|/max(D1,D2)×100을 계산한 뒤, 소수점 둘째 자리로 반올림한 값으로 판정한다.

판정은 아래 순서로 확인하며, 먼저 조건을 만족한 유형으로 확정한다. CVAI가 CI보다 우선한다는 기획 결정을 그대로 따른다.

| 순서 | 유형 | 조건 | 경계값 포함 규칙 |
|---|---|---|---|
| 1 | 따옴이 | CVAI ≥ 3.5 | CVAI가 정확히 3.5이면 따옴이로 판정한다 |
| 2 | 방울이 | CI > 85 | CI가 정확히 85이면 방울이가 아니라 동글이다 |
| 3 | 뾰족이 | CI < 75 | CI가 정확히 75이면 뾰족이가 아니라 짱구다 |
| 4 | 짱구 | 75 ≤ CI < 80 | CI가 정확히 80이면 짱구가 아니라 동글이다 |
| 5 | 동글이 | 나머지 전부 (80 ≤ CI ≤ 85) | 폴백이 아니라 위 조건의 여집합으로 정의된다 |

### 방향 정보 (따옴이 놀이 팁 분기용)

CVAI 판정에 쓰인 D1·D2 중 짧은 대각선이 지나는 뒤통수 쪽이 납작한 쪽이고, 납작한 쪽이 아기가 평소 잘 보던(선호하던) 쪽이다. 놀이 팁의 `{쪽}` 치환은 그 반대쪽, 즉 잘 안 보던 쪽을 쓴다(카피 스펙 §5의 규칙과 동일).

화면 좌우와 아기 좌우의 매핑은 "코가 위로" 촬영 규약을 전제로 하며, 구현 시 포트 코드의 D1·D2 정의에 맞춰 한 번 고정하고 인형 실측 사진으로 좌우가 뒤집히지 않았는지 확인한다. 저장 형태는 `preferredSide ∈ {left, right, unknown}` 하나로 통일하고, 문항 경로(§3)와 같은 필드를 쓴다. 이 값은 기기 안에서만 쓰고 서버로 보내지 않는다.

## 3. 문항 배점과 판정 절차

문항 문구와 순서는 UX 스펙 §4.6을 따르고, 이 문서는 배점만 정한다. 판정 절차는 다음과 같다.

1. 일곱 문항의 응답을 받아 유형별 점수를 합산한다. 7번(월령)은 점수에 반영하지 않는다.
2. 1번 문항에서 "잘 모르겠어요"를 골랐다면 5번·6번 문항의 배점을 2배로 계산한다. 모양을 직접 관찰하지 못한 응답자에게는 습관 신호가 그만큼 무거워진다.
3. 따옴이 3점 이상 → 방울이 3점 이상 → 뾰족이 2점 이상 → 짱구 3점 이상 순서로 확인하고, 먼저 임계에 도달한 유형으로 확정한다. 어디에도 해당하지 않으면 동글이다.

### 배점표

| 문항 | 선택지 | 배점 | 비고 |
|---|---|---|---|
| 1. 위에서 본 머리 느낌 | 동그란 편 | 없음 | 동글이 방향의 응답이라 다른 유형에 점수를 주지 않는다 |
| | 앞뒤로 길쭉한 편 | 뾰족이 +2 | 뾰족이의 유일한 신호이며, 이 응답 하나로 임계(2점)에 도달한다 |
| | 좌우로 넓적한 편 | 방울이 +2 | |
| | 한쪽이 살짝 기울어진 느낌 | 따옴이 +2 | |
| | 잘 모르겠어요 | 없음 | 5번·6번 배점을 2배로 만드는 가중 규칙이 발동한다 |
| 2. 옆에서 본 뒤통수 라인 | 봉긋하게 나온 편 | 짱구 +2 | |
| | 완만하게 둥근 편 | 없음 | |
| | 납작한 편 | 방울이 +2 | |
| | 잘 모르겠어요 | 없음 | |
| 3. 양쪽 귀 위치 | 비슷해 보여요 | 없음 | |
| | 한쪽이 조금 앞으로 나와 보여요 | 따옴이 +2 | 따옴이의 대표 관찰 소견이라 배점이 무겁다 |
| | 잘 모르겠어요 | 없음 | |
| 4. 잘 때 고개 방향 | 왼쪽 / 오른쪽 | 따옴이 +1 | 응답한 쪽을 `preferredSide`로 저장한다(아이 입장 기준) |
| | 양쪽 골고루 | 없음 | |
| | 잘 모르겠어요 | 없음 | `preferredSide`는 unknown으로 남고 팁은 방향 폴백을 쓴다 |
| 5. 등을 대고 누워 있는 시간 | 대부분 누워 있어요 | 방울이 +1 (가중 시 +2) | |
| | 안겨 있거나 엎드리는 시간도 꽤 있어요 | 없음 | |
| | 잘 모르겠어요 | 없음 | |
| 6. 엎드려 노는 시간 반응 | 좋아하고 잘 버텨요 | 짱구 +1 (가중 시 +2) | 응답값은 놀이 팁 선택 로직에도 저장한다 |
| | 조금 하다 힘들어해요 | 없음 | |
| | 아직 안 해봤어요 | 없음 | |
| 7. 월령 | (전 선택지) | 없음 | 놀이 팁의 3개월 전/후 분기에만 쓴다 |

### 도달 가능성 검증

- 따옴이는 최대 5점(2+2+1)이고, 임계 3점에 도달하는 조합은 "기울어진 느낌+귀", "기울어진 느낌+고개 방향", "귀+고개 방향"의 세 갈래다. 관찰 신호 두 개가 겹쳐야 배정되므로 고개 방향 하나만으로는 따옴이가 나오지 않는다.
- 방울이는 최대 5점(2+2+1)이고 "넓적+납작", "넓적+눕기", "납작+눕기" 조합으로 임계에 도달한다. 1번을 모른다고 답한 경우에도 "납작한 편"과 가중된 눕기(+2)로 도달할 수 있다.
- 뾰족이는 1번의 "앞뒤로 길쭉한 편" 하나로만 도달한다. 1번을 모른다고 답한 경로에서는 뾰족이가 나오지 않는데, 희소 유형은 관찰 확신이 있을 때만 배정한다는 의도된 결과다.
- 짱구는 "봉긋+엎드려 잘 버텨요"(2+1)로 임계에 도달하고, 1번 모름 경로에서는 가중된 6번(+2)과 봉긋(+2)으로 도달한다.
- 동글이는 위 어디에도 해당하지 않는 모든 응답 조합을 받는다. "전부 모르겠어요"로 일관한 응답도 동글이가 되며, 이는 기본값이 무난 유형이라는 기획 §2.2와 일치한다.

## 4. 사진 품질 검사 (sanity check)

threshold 0.5로 이진화한 마스크에서 최대 연결 성분을 잡아 아래 다섯 항목을 검사한다. 하나라도 "실패"면 품질 실패 폴백(UX §4.5 첫 행)으로 보낸다. 실패는 없지만 "경계"에 걸린 항목이 하나라도 있으면 "간신히 통과"로 분류하는데, 이때 조준선이 꺼져 있었다면 재촬영 권유 안내(UX §4.5 둘째 행)를 띄우고, 켜져 있었다면 그대로 진행한다. 모든 항목을 통과하면 바로 판정으로 넘어간다.

| 검사 항목 | 정의 | 통과 | 경계 | 실패 |
|---|---|---|---|---|
| 면적비 | 최대 성분 픽셀 수 ÷ 256² | 0.18~0.60 | 0.12~0.18 또는 0.60~0.70 | 0.12 미만 또는 0.70 초과 |
| 성분 지배율 | 최대 성분 픽셀 수 ÷ 전체 마스크 픽셀 수 | 0.90 이상 | 0.80~0.90 | 0.80 미만 |
| 솔리디티 | 성분 면적 ÷ 볼록 껍질 면적 | 0.92 이상 | 0.88~0.92 | 0.88 미만 |
| 중심 이탈률 | 성분 무게중심과 화면 중심의 거리 ÷ 256 | 0.15 이하 | 0.15~0.25 | 0.25 초과 |
| 측정 타당성 | 측정된 CI와 CVAI의 범위 | CI 55~130이면서 CVAI 15 미만 | 없음 | 범위 밖 |

각 수치의 근거는 다음과 같다. 면적비 하한은 머리가 화면 폭의 3분의 1을 넘게 차지해야 축 측정이 픽셀 단위 오차에 흔들리지 않는다는 데서 오고, 상한은 머리가 프레임에 잘리기 시작하는 지점이다. 성분 지배율과 솔리디티는 배경 오검출과 파편난 마스크를 거른다(머리 마스크는 볼록에 가깝다). 중심 이탈률은 조준선 타원의 유도 범위와 짝을 이룬다. 측정 타당성은 마스크 모양이 그럴듯해도 측정이 해부학적으로 불가능한 값을 내면 사진 문제로 간주하는 최종 방어선이다.

경계 구간 표기는 하한 포함·상한 미포함으로 읽는다. 예를 들어 면적비 0.18은 통과이고 0.12는 경계다.

## 5. 두 경로의 일관성

사진 경로와 문항 경로는 서로 다른 근거로 같은 다섯 유형에 도달하므로, 같은 아기라도 경로에 따라 결과가 다를 수 있다. 이것은 결함이 아니라 설계다. 사진은 형태 측정이고 문항은 보호자의 관찰이며, 어느 쪽도 "정답"으로 표시하지 않는다. 다만 두 경로 모두에서 방향 정보와 월령이 같은 필드(`preferredSide`, 월령 구분)에 저장되어 놀이 팁 분기가 동일하게 동작해야 한다.

## 6. 경계값 튜닝 계획

- 식별자 없는 익명 집계로 유형 분포를 모니터링한다. 기대 분포는 동글이가 가장 많고 뾰족이가 가장 적은 모양이다.
- 분포가 기대와 크게 어긋나면 — 예를 들어 한 유형이 절반 가까이를 차지하거나 뾰족이가 전혀 나오지 않으면 — 짱구/동글이를 가르는 CI 80 경계와 품질 검사 수치를 우선 조정한다. 기획 §2.2도 80 경계를 실측 조정 대상으로 지목했다.
- 수치는 어디에도 노출되지 않으므로 경계를 조정해도 카피·카드 에셋 재작업은 발생하지 않는다. 상수 모듈과 이 문서만 바꾸면 된다.
- 스파이크에서 확인한 런타임 간 CVAI 편차(Dart 대비 최대 0.27)는 3.5 경계 인접 사진의 판정을 가를 수 있다. 웹 배포 후의 튜닝은 웹 런타임 실측 분포만 기준으로 삼고, Dart 원본과의 일치는 더 이상 판정 기준으로 쓰지 않는다.
- 문항 배점의 튜닝 신호는 문항 경로의 유형 분포와 "잘 모르겠어요" 선택률이다. 특정 문항의 모름 선택률이 지나치게 높으면 배점 조정보다 문항 문구 개선(UX 스펙 소관)을 먼저 검토한다.

## 7. 소관 경계 (이 문서가 정하지 않는 것)

- 문항·선택지 문구와 화면 흐름 → UX 설계 스펙.
- 통계 노출 전환 임계값, 계측 이벤트에 유형을 싣는 방식 → 공유·앱 진입 플로우 티켓.
- 판정 결과 저장 범위와 동의 문구 → 법률 검토 티켓.
- 배점·경계값 상수의 코드 배치와 모듈 구조 → 구현 티켓.
