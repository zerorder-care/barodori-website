# 아기 두상 유형 테스트 — 바이럴 페이지 설계

> 상태: 기획 확정, 기술 스파이크 전
> 대상: barodori.com 서브패스 (예: `/[locale]/head-test`)
> 관련 자산: barodori-app git 히스토리 `0e2467a3` (두상 측정 ML 파이프라인), `zerorder-care/barodori-ml` (모델 원본)

## 1. 목적과 포지셔닝

MBTI류 바이럴 테스트를 만들어 오가닉 유입을 확보하는 것이 목적이다. 타깃은 신생아에서 영아까지 키우는 부모, 특히 엄마이고, 유통 채널은 맘카페·인스타그램·육아 커뮤니티다.

콘텐츠 수명은 두 갈래로 설계한다.

- **단발 바이럴**: 결과 카드를 공유하고, 공유를 본 사람이 다시 테스트에 들어오는 루프를 만든다.
- **상시 검색 유입**: "사두 자가진단"류 검색 키워드는 사경·두상 정보 아티클(MDX)이 받는다. 아티클과 테스트를 상호 링크로 이어 본 도메인의 SEO 자산으로 쌓고, 테스트 페이지 자체에는 검색용 의학 키워드를 싣지 않는다.

벤치마크로 삼은 사례는 다음과 같다. 트렌드 능력고사가 198만 명, 배민 치믈리에 온라인 모의고사가 57.8만 명 참여했고, 아드리엘 MaBTI는 좁은 B2B 타깃인데도 1주 만에 1만 명이 참여했다. W컨셉×푸망 콜라보는 2주간 18만 플레이에 광고 CTR 8.6%를 기록했다. 이들의 공통 성공 조건은 로그인이나 설치 없이 1~3분 안에 끝나고, 결과 카드를 공유할 수 있으며, 결과 페이지에서 다음 행동으로 자연스럽게 이어진다는 점이다.

## 2. 핵심 기획 결정

### 2.1 프레임: "특성"이지 "진단"이 아니다 — 구조로 달성한다

진단처럼 보이느냐 아니냐는 디스클레이머 문구가 아니라 구조가 결정한다. 그래서 다음 원칙을 구조에 심는다.

1. 의학 용어(사두·단두·주상두·비대칭)는 사용자에게 보이는 어떤 레이어에도 노출하지 않는다.
2. 유형 사이에 심각도 서열을 만들지 않는다. 모든 유형이 같은 포맷, 같은 분량, 같은 톤을 가진다.
3. 결과에 붙는 액션은 "교정 팁"이 아니라 **유형별 놀이 팁**으로 쓴다. 놀이의 실체는 반대쪽 고개 돌리기, 터미타임 같은 바로도리 운동이다.
4. 병원 상담 안내는 모든 유형에 공통으로 붙는 푸터 한 줄로만 둔다. ("두상이 걱정될 땐 소아과·재활의학과 전문의와 상담하세요")
5. CI/CVAI 수치는 절대 노출하지 않는다. 측정·진단 소프트웨어로 보이는 순간 의료기기 판정 리스크가 생기기 때문이다. 수치는 내부 판정에만 쓴다.
6. 카피는 유형명이 의학 분류와 나란히 놓인 채 읽혀도 성립하게 쓴다. 어떤 유형이 나와도 결과 카드가 아이에 대한 애정 표현으로 읽히는 것이 카피의 합격 기준이다.
7. 앱 CTA는 걱정의 해결책이 아니라 놀이의 확장으로 잇는다.

정서 기준도 분명히 한다. 맘카페의 두상 담론은 "아기 두상은 엄마의 죄가 아닙니다" 같은 죄책감 위로 서사로 소비된다. 결과가 "잘못 키웠네"로 읽히는 순간 이 테스트는 실패다. 다섯 유형 모두 동등하게 사랑스러워야 한다. 이 기준으로 유형별 카피 5종을 검수한다.

### 2.2 5유형 체계

의학 분류(사두/단두/주상두/일반)는 내부 뼈대로만 쓰고, 사용자에게는 캐릭터 이름이 붙은 5개 유형으로 보여준다. "일반" 유형을 따로 두지 않는 것이 판정 구조를 없애는 핵심 장치다.

| 내부 뼈대 | 사용자 유형 | 판정 기준 (내부 전용) | 비고 |
|---|---|---|---|
| 사두 | 따옴이 (따옴표) | CVAI ≥ 3.5 | 좌/우는 화면에 노출하지 않는다. 사진 측정(D1·D2 방향)이나 고개 방향 문항에서 얻은 방향 정보는 내부 판정에 함께 저장해두고 놀이 팁 분기에 쓴다 |
| 단두 | 방울이 | CI > 85 | |
| 주상두 | 뾰족이 | CI < 75 | 드물기 때문에 레어 유형으로서 희소성이 있다 |
| 일반(분화) | 짱구 | 75 ≤ CI < 80 | "자랑 유형" 역할 |
| 일반(분화) | 동글이 | 80 ≤ CI ≤ 85 | 기본값이 되는 "무난 유형" |

사진 측정의 판정 우선순위는 CVAI가 CI보다 앞선다. 경계값, 특히 짱구/동글이를 가르는 80은 실측 분포를 보고 조정한다.

### 2.3 입력 방식: 사진 측정이 기본, 문답은 폴백

- **1차: 사진 측정** — barodori-app에 있던 두상 측정 모델을 브라우저 온디바이스(ONNX Runtime Web, WASM/WebGPU)로 재활용한다. "사진은 기기 안에서만 처리되며 서버로 전송되지 않습니다"라는 문장이 프라이버시 스토리이자 차별화 포인트가 된다. "AI가 사진 한 장으로 두상 유형을 알려준다"는 공유 문구 자체도 다른 테스트와의 차별점이다. 판정 결과와 좌/우 방향 정보도 기기 안에서만 쓰고 서버에 저장하지 않으며, "같은 유형 아기 n%" 통계는 식별자 없는 익명 집계 카운트로만 만든다.
- **2차: 문항 폴백** — 세그멘테이션 신뢰도가 낮거나(마스크 sanity check 실패) 사용자가 사진 촬영을 원치 않으면 8문항 문답으로 판정한다. 문항은 3장에 정리했다.
- **촬영 가이드** — 촬영 화면에 조준선 오버레이를 둔다. 머리 실루엣 타원(중앙·크기 유도), "코가 위로" 방향 표시(좌/우 판정 규약), 십자선(기울기 기준)으로 구성하고, 토글로 끌 수 있되 기본은 켜진 상태다. 같은 피사체도 촬영 각도에 따라 CVAI가 유형 경계를 넘나드는 것이 스파이크에서 확인되어, 조준선이 판정 안정성의 핵심 장치다. 조준선을 끈 상태에서 마스크 sanity check가 간신히 통과하면 "가이드에 맞춰 다시 찍으면 더 정확해요" 안내를 띄운다. 갤러리 업로드 경로에는 업로드 후 미리보기에서 코가 위를 향하도록 회전하는 사후 정렬 UI를 둔다.

### 2.4 배치: barodori.com 서브패스, 독립 번들

별도 도메인을 파지 않고 본 사이트(Next.js 16 App Router, 풀-SSG)에 얹는다. 이유는 다음과 같다.

- 검색 유입 자산이 본 도메인에 쌓인다. 새 도메인은 SEO 신뢰도 0에서 시작해야 한다.
- 아기 사진을 다루는 기능은 브랜드 도메인에 있어야 수용도와 신뢰를 확보할 수 있다.
- 기존 사경 아티클(MDX) ↔ 테스트 ↔ 앱 CTA가 한 도메인 안에서 순환한다.
- GA4 + Amplitude 계측 인프라와 `[locale]` i18n 라우팅을 그대로 재사용할 수 있다.

다만 테스트 페이지는 클라이언트 컴포넌트 섬으로 분리해서, 추론 런타임과 10MB짜리 모델을 해당 라우트에 진입할 때만 lazy 로드한다. 본 사이트 번들에는 섞지 않는다.

### 2.5 CTA

결과 카드에서 유형별 놀이 팁으로, 놀이 팁에서 "이 유형 아기와 매일 놀아주는 법은 바로도리 앱에서"로 이어지는 흐름이다. 앱 연결은 Airbridge 링크를 쓰며, `barodori.airbridge.io` 딥링크 도메인은 이미 앱에 등록되어 있다.

## 3. 문항 설계 (폴백 겸 놀이 팁 개인화)

관찰 4문항, 습관 3문항, 개월수 1문항으로 구성하고 소요 시간은 1분 안팎으로 잡는다. "검사"가 아니라 "우리 아기 관찰 놀이"라는 톤을 유지한다.

| # | 문항 | 신호 |
|---|---|---|
| Q1 | 위에서 내려다본 머리 느낌 (보름달/타원/좌우 넉넉/한쪽 비스듬/모름) | 모양 축의 핵심. "모름"이면 습관 파트에 2배 가중 |
| Q2 | 옆에서 본 뒤통수 라인 (봉긋/완만/수직) | 짱구 vs 동글이 vs 방울이 |
| Q3 | 정면에서 양쪽 귀 위치 (비슷/한쪽 앞으로[좌·우]/모름) | 따옴이의 대표적인 관찰 소견 |
| Q4 | 사진 잘 나오는 각도가 고정되어 있는지 | 비대칭 보조 신호 |
| Q5 | 잘 때 고개 방향 (왼쪽/오른쪽/골고루/천장) | 따옴이 신호이자 내부 좌/우 판정. **"아이 입장 기준"이라는 안내가 필수(앱 규약과 일치)** |
| Q6 | 하루 중 등 대고 눕는 시간 | 방울이 축의 원인 신호 |
| Q7 | 터미타임 반응 | 놀이 팁 개인화에 사용, 짱구 신호도 겸함 |
| Q8 | 개월수 (0~2/3~5/6~11/12+) | 점수에는 반영하지 않음. 놀이 팁을 3개월 전/후로 분기(앱과 동일 기준)하고, 0~5개월에만 "말랑한 시기" 문구 한 줄 추가 |

문항 판정은 따옴이(3점 이상) → 방울이(3점 이상) → 뾰족이(2점 이상) → 짱구(3점 이상) 순으로 확인하고, 어디에도 해당하지 않으면 동글이로 분류한다.

## 4. 결과 카드 구조 (5유형 공통 포맷)

1. 유형명 + 도리 캐릭터 일러스트 (두상 실루엣 모티브)
2. 특성 서술 3줄 — 성격처럼 쓴다 ("왼쪽 세상이 제일 궁금한 탐험가…")
3. 이 유형 아기가 좋아하는 놀이 2개 (개월수에 따라 분기)
4. "같은 유형 아기 n%" (식별자 없는 익명 집계 기반)
5. 공유 버튼 (OG 카드 = 유형 일러스트)
6. 공통 푸터 1줄 (전문의 상담 안내)
7. 앱 CTA (Airbridge)

공유 훅은 유형마다 따로 설계한다. 뾰족이는 희소성("상위 n%만 나오는 유형"), 짱구·동글이는 자랑, 따옴이·방울이는 개성과 공감을 축으로 잡는다. 유형별 공유율을 따로 계측해서 공유 훅 가설을 검증한다.

## 5. 기술 스펙 (barodori-app `0e2467a3`에서 복원)

- **모델**: U-Net + MobileNetV2 구조의 FP16 TFLite 모델이 10MB짜리 2종(`v2`, `v2.1-bnd10` 기본) 있다. 입력은 `[1,256,256,3]` RGB를 0~1로 정규화한 값이고, 출력은 `[1,256,256,1]` 확률 마스크이며 threshold는 0.5다. 모델 파일은 barodori-app git 히스토리에서 복구할 수 있다. 웹에서는 barodori-ml의 원본 모델을 ONNX로 내보내 ONNX Runtime Web(WASM/WebGPU)으로 구동한다.
- **전처리**: 짧은 변 기준으로 중앙 정방형 크롭을 하고, 256×256으로 리사이즈한 뒤 255로 나눈다. Canvas API로 재현할 수 있다.
- **측정**: 마스크의 무게중심(area centroid)을 잡고 레이트레이싱으로 축 길이를 잰다. AP(수직)/ML(수평)/D1·D2(AP축 ±30°)를 구한 뒤 CI = ML/AP×100, CVAI = |D1−D2|/max(D1,D2)×100으로 계산한다. 참고용 정상 범위는 CI 75~85, CVAI < 3.5다.
- **포팅 규모**: 순수 로직은 약 570줄(측정 184 + 마스크 후처리 231 + 컨투어 추출 151)로, Dart에서 TS로 직역하는 수준이다. 카메라 스트림 처리(YUV 변환 등)는 웹에서는 필요 없다.
- **컨투어 오버레이**: 측정 결과 위에 윤곽선을 렌더링하는 것은 선택 사항이지만, "AI가 인식했다"는 시각 효과를 주기 때문에 가치가 있다.

## 6. 리스크와 대응

| 리스크 | 대응 |
|---|---|
| ONNX 변환 과정에서 모델 출력이 달라질 가능성 | **최우선 스파이크**로 모델 로드와 샘플 추론을 검증하고, 같은 사진에 대해 원본 파이프라인과 마스크 출력이 일치하는지 확인한다. 문제가 있으면 tfjs 포맷 변환으로 우회한다 |
| 좌우 판정이 촬영 방향(코가 위)을 전제로 함 | 촬영 화면에 조준선 오버레이(기본 켜짐, 2.3 참조)를 둔다. 구 앱 측정 화면(671줄)의 UX를 참고한다 |
| 야생 사진 품질 문제 (조명·배경·머리카락) | 마스크 면적·형상 sanity check에 실패하면 문답으로 폴백한다 |
| 의료기기/진단으로 오인될 가능성 | 수치 비노출 + 특성 프레임 + 공통 푸터로 대응한다. 앱의 비의료 웰니스 포지셔닝과도 일관된다. 출시 전에 의료기기·의료광고 관점의 법률 검토를 거친다 |
| 판정 결과를 서버에 남기면 아동 건강 관련 민감정보 처리가 될 가능성 | 판정 결과와 방향 정보는 기기 안에서만 쓰고, 서버에는 식별자 없는 익명 집계만 남긴다. 계측 이벤트에 유형을 싣는 방식과 동의 문구는 법률 검토 범위에 포함한다 |

## 7. 남은 작업 (순서대로)

1. 스파이크: ONNX Runtime Web에서 모델 추론을 검증하고, 원본 파이프라인과 출력 동등성 확인 (레포 밖 스크래치패드에서 진행)
2. 유형별 카피 5종 작성 + 캐릭터 일러스트 발주
3. 촬영 가이드 UX 설계 후 라우트 구현 (`/[locale]/head-test`)
4. 실측 분포를 기반으로 유형 경계값 튜닝 (필요하면 barodori-ml manifest 확인)
5. 계측 설계: 진입 → 촬영/문답 → 결과 → 공유/앱 클릭으로 이어지는 퍼널과 유형별 공유율 (GA4·Amplitude)
6. 의료기기·의료광고·개인정보(판정 결과 저장 범위, 동의 문구) 관점의 법률 검토 (문구, 아티클 링크 구조 포함)
7. 유통 계획: 맘카페·육아 인플루언서·앱 내 커뮤니티를 활용하고, 사경 아티클과 상호 링크를 건다
